## Problem Statement

当前界面虽然已经有背景、侧栏、卡片、浮层四层表面令牌，但实际分区仍主要靠 1px 发丝线和「框套框」：顶栏底边、会话头底边、设置侧栏右边、卡片 ring、设置行边框、管理列表行边框、执行组边框叠加在一起。全站组件层约有 140 处 border/ring 引用，其中大量用于布局分区而不是交互提示。

这带来三个用户可感知的问题：

1. **深色下层级弱**：画布、侧栏、卡片在暗色下明度过于接近，用户很难不看线就判断「这是侧栏 / 这是卡片 / 这是一个独立的执行组」。
2. **浅色下像线框图**：卡片和画布几乎同白，只能靠很淡的描边辨认；一旦去掉线，界面就会失去结构。
3. **框套框**：对话执行组、工具卡、确认卡、设置卡、设置行、管理列表行各自再套一层描边，阅读路径被切碎，和 Codex / Claude / Linear 这类「内容优先、chrome 后退」的桌面工具观感有明显差距。

主题系统也不完整：当前只有明暗模式 + 单个强调色下拉，强调色用十六进制值直接覆盖品牌变量，没有主题级表面、语义状态、代码高亮和可访问性配对；没有 Nord，也没有主题预览。侧栏的太阳/月亮按钮只能切换明暗，不能选择主题。设置与对话使用两套视觉语言，用户会觉得像两个产品拼在一起。

用户希望的新方向是：**不靠明显线条分区，用不同但差异克制的颜色区块表达层级；内置 Nord，并提供可选择的其他主题。**

## Solution

把界面从「边框驱动」改为「表面驱动」：

- **四类语义表面**：主画布、全局 chrome（顶栏 / 对话侧栏 / 设置导航）、内容面板（执行组 / composer / 设置分组 / 列表）、浮层（菜单 / 对话框 / toast）。相邻表面只差一到两级明度，目标对比比例约 1.05–1.30，靠色块、间距和圆角建立结构。
- **移除常驻分区线**：顶栏、会话头、设置侧栏、卡片、列表行、对话框、popover 默认不再有 border/ring；交互反馈改用 hover 底色、选中色、focus ring 和阴影。
- **保留功能性边界**：输入框仍有可识别底色与 focus ring；复选框、resize 手柄、Markdown 表格、diff、代码块等数据/控件结构可以保留必要的细线。高对比主题可以显式启用描边。
- **Nord 作为默认推荐主题**：使用 Nord 官方 Polar Night / Snow Storm / Frost / Aurora 作为表面与强调色基础，并对文字态语义色做 AA 对比度修正。新增石墨、纸墨、高对比三个主题；每个主题都有浅色与深色两套完整令牌。
- **主题与明暗模式分离**：主题决定整套色板，明暗模式只决定同一主题的 light / dark 变体。Nord、石墨、纸墨、高对比四套主题都有完整的浅色与深色版本，`system` 跟随操作系统。
- **主题库替代自由强调色**：外观页展示紧凑的主题分段按钮和 light / dark / system 分段选择；侧栏底部提供快速主题切换。主题即时生效、持久化，并在首帧前应用，避免闪白/闪黑。
- **全站统一视觉语法**：对话流、composer、执行组、确认卡、设置页、管理页列表、任务结果区、对话框、菜单、toast、更新卡片全部使用同一套表面与状态令牌。强调色只出现在当前选中、focus、运行态和少量关键操作上，主按钮继续保持中性高对比，不做满屏彩色。
- **可验证**：每个主题的正文、元数据、强调文字、状态文字、focus ring 和主按钮配对都通过对比度测试；相邻表面色差同时设上限与下限，防止「完全看不见」或「色块跳变」。

## User Stories

1. 作为桌面用户，我希望应用看起来像一个连续的工作区，而不是一组带边框的盒子，以便长时间使用时视觉噪音更低。
2. 作为深色模式用户，我希望侧栏、主画布和卡片靠克制的明度差区分，以便不用盯着细线也能理解层级。
3. 作为浅色模式用户，我希望卡片和画布不是同一块白纸，以便在明亮环境下也能看清内容边界。
4. 作为用户，我希望顶栏、侧栏、会话头、设置导航和卡片不再使用常驻分割线，以便界面更接近 Codex 式的干净工作区。
5. 作为用户，我希望当前会话项用柔和的强调色底纹和文字色表示，而不是左侧竖条或描边，以便选中态清楚但不刺眼。
6. 作为用户，我希望顶栏、对话侧栏和设置导航共享同一层 chrome 颜色，以便全局区域形成一个整体。
7. 作为用户，我希望会话头不画水平线，滚动时仍然能看清标题和操作，以便阅读内容时 chrome 后退。
8. 作为用户，我希望 composer 是抬起的柔和面板而不是描边盒子，以便输入区有存在感但不抢正文。
9. 作为用户，我希望执行过程是一整块柔和面板，工具行不再各自套框，以便我能快速扫过一整轮工具调用。
10. 作为用户，我希望工具确认卡用状态底纹、图标和文字表达危险/等待，而不是高对比警告边框，以便警示仍然明显但不破坏整体克制感。
11. 作为用户，我希望思考过程不再靠左侧竖线表示层级，而是用低对比底纹和缩进组织，以便长对话里的过程块更安静。
12. 作为用户，我希望日期分隔不再由两条横线组成，而是用留白和元数据文字表示，以便减少无意义线条。
13. 作为用户，我希望用户消息用柔和的品牌色底纹、助手消息保持无气泡正文，以便阅读重心落在回答上。
14. 作为用户，我希望设置页的分区靠间距和面板底色建立，而不是卡片套卡片、设置行逐行描边，以便长设置页更好扫读。
15. 作为用户，我希望设置行有稳定的左右对齐和垂直节奏，但不需要每行一条边界线，以便表单更安静。
16. 作为用户，我希望 Agents、团队、Skills、MCP、模型等管理列表是连续的行式面板，而不是每个条目一张描边卡片，以便列表密度和层级更一致。
17. 作为用户，我希望右侧任务结果区用独立但克制的 chrome 色与对话区区分，以便并排工作时知道哪边是对话、哪边是验收区。
18. 作为用户，我希望对话框和弹出菜单只靠浮层背景与阴影区分，不再加一圈 ring，以便浮层干净且仍然明显高于页面。
19. 作为用户，我希望 toast、更新卡片、错误提示也使用主题令牌，以便任何系统反馈都不会破坏整体主题。
20. 作为用户，我希望应用内置 Nord 主题，以便我可以直接选择偏冷、低饱和的蓝灰配色。
21. 作为新用户，我希望默认就是 Nord 主题，以便第一眼看到设计完整的新界面，而不是旧的强调色拼装。
22. 作为用户，我希望主题选择保持紧凑，并且切换后立即可见完整界面效果，以便不离开设置就能比较主题。
23. 作为用户，我希望除了 Nord 还能选择石墨主题，以便保留接近当前中性灰的专业观感。
24. 作为用户，我希望还能选择纸墨主题，以便白天或偏好暖色背景时使用更柔和的界面。
25. 作为低视力用户，我希望有高对比主题可选，以便在需要时使用更大的文字/背景对比和明确控件边界。
26. 作为用户，我希望 light / dark / system 和主题预设分开选择，以便同一个 Nord 主题可以跟随系统或固定深色。
27. 作为用户，我希望切换主题立即生效，不需要重启、保存或刷新窗口，以便快速比较。
28. 作为用户，我希望主题选择持久化，并在应用首帧前应用，以便启动时没有明显的闪白或闪黑。
29. 作为用户，我希望侧栏底部可以快速打开主题切换器，而不是只能在设置页里找，以便高频调整外观。
30. 作为键盘用户，我希望主题和模式选择可以用方向键、Tab、Enter/Space 操作，并有可见 focus，以便不依赖鼠标。
31. 作为读屏用户，我希望主题选择暴露单选组语义、当前选中项名称和主题描述，以便知道正在选择什么。
32. 作为读屏用户，我希望当前选中态不只靠颜色表达，同时有可读的选中状态或 aria 状态，以便色觉差异下也能确认。
33. 作为用户，我希望每个主题的正文、元数据和状态文字都满足 WCAG AA，以便美观不以可读性为代价。
34. 作为键盘用户，我希望所有按钮、菜单、输入框和选择控件在任意主题下都有清楚但不过分抢眼的 focus ring，以便焦点位置始终可见。
35. 作为使用 system 模式的用户，我希望系统切换深浅色时界面实时跟随，并保持当前主题不变，以便不用重新选择主题。
36. 作为用户，我希望字体大小、对话栏宽、会话侧栏宽度等偏好不受主题切换影响，以便换主题不会打乱阅读布局。
37. 作为老用户，我希望升级后保留原来的明暗模式、字号和栏宽偏好，即使旧的强调色不再使用，也不会导致配置损坏或首屏空白。
38. 作为对动效敏感的用户，我希望主题切换和状态过渡尊重 reduced-motion，以便没有不必要的颜色/位移动画。
39. 作为开发者，我希望代码块和 diff 在每套主题下都有语义清楚且可读的高亮色，而不是只有两套全局紫色/绿色，以便内容可读性随主题一致。
40. 作为维护者，我希望所有页面只使用语义令牌，不再在组件里写死十六进制或 amber/emerald/red 调色板，以便新增页面不会重新引入边框和杂色。
41. 作为维护者，我希望设计系统文档明确「什么是允许的线、什么是禁止的线」，以便后续迭代不会把边框分区加回来。
42. 作为回归测试者，我希望浏览器桩能一键切换主题和明暗模式，以便对四套主题、两种模式、全部关键页面做视觉走查并留下基线截图。

## Implementation Decisions

### 1. 主题模型与配置

- 外观偏好拆成两个独立字段：主题预设（`nord` | `graphite` | `paper` | `contrast`）与明暗模式（`light` | `dark` | `system`）。默认值建议为 `nord` + `dark`，保留现有字号、对话栏宽、侧栏宽度等无关偏好。
- 主题预设决定一整套语义令牌；明暗模式只决定使用同一预设的 light 或 dark 变体。`system` 只影响模式，不改变预设。
- 移除自由强调色选择器与旧 `accent` 渲染路径。旧配置缺少主题预设时回退 `nord`，未知预设也回退 `nord`；旧 `accent` 字段不再参与渲染，下一次保存自然清理。迁移不得阻塞启动，不得因旧字段导致配置校验失败。
- 主题元数据包含中文名称、简短描述和预览标签；不在组件里散落主题颜色值。
- 不引入用户自定义主题、主题市场、按项目/Agent/会话覆盖主题。

### 2. 语义令牌契约

- 表面令牌固定为四类：`canvas`（主阅读/工作画布）、`chrome`（顶栏、对话侧栏、设置导航）、`panel`（执行组、composer、设置分组、管理列表、任务结果面板）、`overlay`（菜单、对话框、toast）。
- 每类表面有对应的前景、次级前景和 hover/selected 派生色；状态色包含 `danger`、`warning`、`success` 及其 `*-soft` 底纹和可读文字变体。
- 强调色只用于：当前导航/会话项、focus ring、运行中指示、少量链接与关键图标。主按钮继续使用中性高对比 `primary`，不把强调色扩展为全屏背景。
- 字号阶梯、Geist + 中文回退字体栈、正文 15px/1.7、元数据下限 12px 保持不变；本次不换字体、不换图标库。
- 圆角保持克制：控件 8px、面板 12px、大面板/对话框 16px、用户气泡 16px；避免同一屏出现过多圆角档位。
- 间距按页面 32、区块 24、组 16、行内 8/12 的节奏；用间距替代原本由边框承担的分组职责。
- `border` / `line` 令牌降级为功能令牌：只允许出现在输入控件、复选框、resize 手柄、Markdown 表格、diff、代码块、高对比主题与 forced-colors 场景。布局容器、卡片、列表行、侧栏、顶栏、会话头、对话框、popover 一律不得用常驻 border/ring 做分区。

### 3. 表面差与「无线条」规则

- 主布局相邻表面（canvas ↔ chrome、chrome ↔ panel）的对比比例目标为 1.05–1.30；超过 1.35 视为色块跳变，低于 1.05 视为不可感知。`overlay` 允许与 `panel` 同色，由浮层阴影承担与页面的分离。
- 深色主题中 chrome/panel/overlay 相对 canvas 逐级更亮；浅色主题中 chrome 相对 canvas 略深，panel/overlay 相对 canvas 更亮。明暗变化方向可以不同，但语义角色不能变。
- 取消所有布局级 border/ring：顶栏底边、会话头底边、设置侧栏右边、卡片外圈、管理列表行、设置行、工具组、确认卡、对话框、popover、toast 的常驻描边全部移除。
- 导航/会话/候选选中态使用 `accent-soft` 底纹 + `accent-text` 文字 + 必要的可访问状态；分段控件使用 `choice-selected` / `choice-selected-danger` + `foreground` 文字 + Check 图标（避免软底纹上的文字对比不足）；不使用左侧竖条、左侧 2px 色条或高对比描边。
- hover 使用比当前表面高一档的柔和底色；focus 使用 2px 强调色环 + 少量外扩，不靠加粗边框。
- 不使用满屏渐变、玻璃拟态、发光描边、彩虹色图标或大面积品牌色。表面差和内容排版是主要视觉语言。

### 4. Nord 主题映射

Nord 使用官方 Polar Night / Snow Storm / Frost / Aurora 作为身份基础；原始 Aurora 色在部分背景上不满足 4.5:1，因此状态文字使用同色相的加亮/加深变体，原始色只用于图标、进度和小面积底纹。

| 语义角色 | Nord 深色 | Nord 浅色 |
|---|---|---|
| canvas | `#2E3440` | `#ECEFF4` |
| chrome | `#3B4252` | `#E5E9F0` |
| panel | `#434C5E` | `#FFFFFF` |
| overlay | `#4C566A` | `#FFFFFF` |
| foreground | `#ECEFF4` | `#2E3440` |
| muted foreground | `#D8DEE9` | `#4C566A` |
| accent（装饰/底纹） | `#88C0D0` | `#5E81AC` |
| accent text（文字/链接） | `#9BD3E0` | `#4C6A91` |
| primary | `#ECEFF4` | `#2E3440` |
| primary foreground | `#2E3440` | `#ECEFF4` |
| danger text | `#F5C2C7` | `#A63D4A` |
| warning text | `#EBCB8B` | `#7A5A12` |
| success text | `#BED6AB` | `#3F6B3F` |
| focus ring | `#88C0D0` | `#4C6A91` |

- Nord 深色的 canvas/chrome/panel/overlay 对比比例约为 1.24 / 1.17 / 1.17；浅色 canvas/chrome 约为 1.06，chrome/panel 约为 1.22，满足「能感知但不跳变」。
- 代码高亮使用 Nord Frost 与 Aurora 的四类语义槽位；每个主题单独定义，不共享固定紫色/绿色。
- Nord 官方色值和来源写入设计系统文档；实现时以对比度测试结果为准，不照搬低对比原始色作为正文。

### 5. 其他主题

- **石墨**：延续当前微冷中性灰的专业观感，蓝灰强调色；用于不想使用 Nord 蓝调的用户。
- **纸墨**：暖象牙/米白表面 + 深墨文字 + 暖琥珀强调；深色变体为低色温墨黑，不做成纯棕色调。
- **高对比**：接近黑/白的高对比表面，允许显式控件描边和更清晰的 focus 环；它是可访问性预设，不参与默认「无线条」规则。
- 四套主题都必须有 light/dark 完整令牌；不允许出现某个主题只有深色、浅色回退到别的主题的情况。
- 四套主题使用同一组紧凑文字分段按钮，不再渲染缩略图卡片；切换即预览完整界面，选项说明只在当前设置行显示一次。

### 6. 应用壳层

- 根布局使用 `canvas`；顶栏、对话侧栏、设置导航统一使用 `chrome`；设置内容、聊天阅读区使用 `canvas`；执行组、composer、设置分组、列表容器使用 `panel`；菜单/对话框/toast 使用 `overlay`。
- 顶栏保持当前 40px 高度，但移除底边线；品牌图标继续使用小面积 accent-soft 底纹。
- 对话会话头保持 48px 左右高度，背景并入 canvas，移除底边线；标题、目标徽标、搜索/结果区入口靠间距和弱底纹组织。
- 设置侧栏移除右边线；选中设置标签使用 accent-soft 底纹和 accent-text，不使用左侧竖条。
- 对话侧栏 resize 手柄在静止时完全透明；hover/drag 时显示 2px 强调色提示。它是交互 affordance，不属于常驻分区线。
- 窗口控制按钮 hover 使用 panel/overlay 底色；关闭按钮 hover 使用 danger-soft，不改变整体 chrome 基调。

### 7. 对话流与 Composer

- 执行组由「外框 + 内部工具卡边框 + 行边框」改为单块 `panel` 容器：组头、内容、工具行通过底色、留白和缩进区分，不再逐行描边。
- 确认卡移除 border 与左侧 2px 色条，改为 `warning-soft` / `success-soft` / `danger-soft` 底纹 + 图标 + 可读状态文字；参数区使用 overlay 或 panel 底色，不再套边框。
- 思考过程移除左侧竖线，改为低对比底纹块 + 图标 + 缩进；折叠头保留键盘可达。
- 日期分隔改为居中元数据文字与上下留白，不再画两条横线。
- 用户消息使用 accent-soft 气泡，无 ring；当前轮只提高底纹浓度，不加边框。助手消息保持无气泡全宽正文。
- Composer 使用 panel 底色、16px 圆角、无边框；聚焦时不显示整块包边/ring，由文本光标与内部控件自身焦点提示交互状态。拖拽态使用 accent-soft 底色与文字提示，不依赖虚线边框。
- @ 提及、斜杠菜单、模型菜单使用 overlay 底色 + 阴影，移除 ring；选中的候选项使用 accent-soft。
- 错误消息使用 danger-soft 底纹 + danger 图标/文字，不使用高对比红色描边。
- 代码块使用 panel 底色、无外框、语言标签与复制按钮；diff 使用低对比红/绿行底纹和语义标记，不依赖分隔线。
- 任务结果面板使用 chrome 作为独立区域底色；标签页、文件行、预览区使用底色与间距组织，移除顶部分割线和文件行描边。

### 8. 设置与管理页

- 外观页重做为行式设置：主题、明暗模式、字号、栏宽均使用紧凑分段控件，当前主题说明显示在主题行左侧；移除旧的强调色圆点和主题预览大卡。
- 主题选择即时应用并持久化；不需要单独「预览」按钮。切换失败时保留当前主题并显示可读错误，不静默失败。
- 通用设置改为单列或最多两列的正常网格，不使用 CSS columns 瀑布流；页面标题、分组标题、面板、行控件形成稳定节奏。
- 设置分组使用 panel 底纹，分组标题可在面板外；设置行移除边框，使用 12–16px 垂直内距和 hover/selected 底色。
- Agents、团队、Skills、MCP、模型等管理页统一为「页头 + 行式列表面板」；列表行使用 panel/overlay 底纹和间距，不用逐行边框或每项一张卡片。
- 空态移除虚线边框，改为 panel/overlay 底纹块 + 图标 + 标题 + 说明 + 主操作。
- 对话框、确认框、popover 移除 ring，使用 overlay 底色、阴影和间距；底层内容不做模糊过度。
- 更新卡片、侧栏更新面板、toast、错误条、进度条全部使用语义令牌；状态色只用于图标、标签、进度和底纹。

### 9. 主题应用与持久化

- 根元素同时维护主题预设属性与 `.dark` 类；主题切换只更新属性和类，不重新挂载 React 树。
- 首帧前从本地缓存同步应用主题预设/模式，随后从后端设置校正；不得出现先渲染旧主题再闪切的可见过程。
- 主题切换同步更新 `color-scheme`，让原生滚动条、表单控件和 WebView 默认控件跟随明暗。
- `system` 模式监听系统外观变化；系统切换时只更新 light/dark，不改变主题预设。
- 主题设置沿用现有设置保存通道；新字段加入默认值规范化与导出/导入兼容逻辑。旧的明暗模式、字号、栏宽必须保留。
- 不做全屏颜色渐变过渡；只保留 hover、focus、选中态的短过渡，并在 reduced-motion 下关闭。

### 10. 可访问性与质量护栏

- 每套主题、每种模式的正文/画布、正文/面板、元数据/面板、强调文字/面板、状态文字/底纹、主按钮文字/主按钮、focus ring/相邻表面都必须达到规定的对比度阈值。
- 状态不能只靠颜色表达：确认卡、错误、成功、警告、运行中都必须同时有图标或文字。
- 主题与权限分段控件使用单选组语义和 `aria-checked`；侧栏快速切换器使用可访问名称；所有纯图标按钮补齐 `aria-label`。
- 高对比主题与 forced-colors 情况下允许恢复清晰描边；默认主题仍以表面差为主。
- reduced-motion 下不新增颜色/位移长动画；主题切换不闪烁。

### 11. 文档与实施顺序

- 更新设计系统文档：四类表面、Nord/石墨/纸墨/高对比的令牌表、允许的线/禁止的线、主题迁移说明、对比度证据。
- 更新视觉基线截图：至少覆盖 Nord 深/浅、石墨深、纸墨浅、高对比深，以及对话页、设置外观页、管理列表、对话框、任务结果区。
- 建议拆成四个可独立合并的阶段，不做一个巨型 PR：
  1. **主题核心**：配置字段、令牌契约、Nord/石墨、首帧应用、对比度测试。
  2. **壳层与对话**：顶栏、侧栏、会话头、设置导航、composer、执行组、确认卡、任务结果区。
  3. **设置与管理页**：外观画廊、设置行、列表、空态、对话框/popover、更新卡片。
  4. **主题扩展与固化**：纸墨、高对比、快速切换器、浏览器桩截图、文档与全量走查。
- 每阶段结束必须保持现有功能、快捷键、HITL、任务结果区、主题持久化和全量测试可用。

## Testing Decisions

好的测试只验证外部可观察行为：用户选中的主题、明暗模式解析、持久化结果、可访问状态、对比度契约和实际渲染出来的视觉层级；不依赖组件内部的 class 名、DOM 层级或某个实现函数的中间状态。

### 测试缝（优先复用现有缝，只新增一个高缝）

1. **主题偏好解析纯函数（复用现有主题模块的缝）**：给定主题预设、明暗模式和系统外观，断言最终使用的预设/模式；覆盖默认 Nord、system 跟随、未知主题回退、旧配置只有 themeMode、字体/栏宽等其他偏好不变。先例：现有主题应用与设置规范化测试。
2. **主题令牌契约测试（唯一新增高缝）**：从声明主题令牌的单一来源读取四套主题 × 两种模式的令牌，自动断言正文/元数据/状态/主按钮对比度 ≥ 4.5:1，focus ring 与相邻表面 ≥ 3:1，相邻表面比例在 1.05–1.30。这个缝放在主题令牌层，不在每个组件里重复测色值。
3. **配置规范化与持久化（既有 Go 配置测试缝）**：旧 JSON 缺少主题预设时回退 Nord；未知主题回退 Nord；`themeMode`、`fontScale`、`chatWidth` 等旧字段保留；保存后重新加载结果稳定。先例：现有侧栏/设置字段规范化测试。
4. **主题选择器静态语义测试（复用现有静态渲染测试缝）**：断言四个主题分段选项、单选组/`aria-checked`、中文名称与当前主题说明；不测颜色 class。先例：现有 TopBar/SidebarFooter 静态断言。
5. **浏览器桩全量视觉走查（既有视觉回归缝）**：通过 URL 参数或 localStorage 让 stub 切换预设/模式，覆盖四套主题的浅深组合、对话页、设置外观页、管理列表、对话框和任务结果区；检查相邻表面在 100% 亮度下可感知、无常驻布局线、focus 可见、reduced-motion 生效。先例：现有浏览器桩视觉走查与截图基线。
6. **全量验证**：前端 `tsc`、`npm test`、生产构建，后端既有测试与仓库一键全量验证不回归。

### 视觉验收矩阵

- Nord light / Nord dark：完整走查，作为默认主路径。
- 石墨 dark、纸墨 light：验证非 Nord 主题不是简单换强调色。
- 高对比 dark：验证可访问性预设允许明确控件描边。
- 对话页：侧栏、会话头、用户气泡、助手正文、执行组、确认卡、composer、任务结果区。
- 设置页：外观主题/模式分段控件、通用设置、Agents 列表、对话框、popover、toast、更新卡片。
- 键盘：Tab 到主题与权限选项、方向键切换、Enter/Space 应用、focus ring 不被遮挡。
- reduced-motion：主题切换与展开/折叠无长位移动画。

## Out of Scope

- 用户自定义主题、主题编辑器、主题市场、主题导入/导出。
- 任意强调色自定义；旧 `accent` 的精确颜色不保证迁移，只保证配置不损坏。
- 按项目、Agent、会话、页面覆盖主题。
- 新的导航信息架构、新页面、新功能或对 Agent/Team/MCP/模型行为的改动。
- 新字体、新图标库、新 Logo 或品牌重做；本次保留 Geist + 中文回退栈和 Lucide 图标。
- 移动端重排、新的响应式断点或窄窗口交互模型；现有窗口尺寸行为保持不变。
- 全屏主题过渡动画、像素级截图 diff 自动化、视觉回归 CI 平台接入。
- 后端 RPC、会话存储、任务工作区、A2A、更新器行为；除外观配置字段外不改数据 schema。
- forced-colors 的完整跨平台审计；高对比主题只覆盖应用内可访问性预设。
- 代码高亮引擎替换；只更换主题令牌与颜色映射。

## Further Notes

- **设计依据**：本方案来自对现有截图、壳层、主题模块、设置页和管理页的实际走查；`ui-ux-pro-max` 的 design-system 查询给出 Minimalism & Swiss Style、低动效、density 7 与「文字 4.5:1、focus 可见、reduced-motion」的方向。其 teal/orange 落地页调色板不适用于本产品，因此只采纳排版、层级、克制色彩和无障碍原则，最终颜色以 Nord 与桌面工具场景为准。
- **Nord 的对比度陷阱**：Nord 原始 Aurora 色作为文字在部分深色表面上只有约 2.1–4.4:1，直接拿来当 `--danger`、`--warning`、`--success` 会导致不可读。方案保留原始色用于填充/图标，新增可读文字变体，并把对比度测试作为硬门槛。
- **「无线条」不等于「无边界」**：输入框、复选框、resize 手柄、Markdown 表格、diff、代码块和 forced-colors 仍需要功能性边界。禁止的是用常驻线条承担布局分区，而不是删除所有可访问性 affordance。
- **主要风险**：表面差过小会导致侧栏/画布难分辨；过大又会变成色块跳变。用 1.05–1.30 的数值区间和 100% 亮度下的真实截图双重验收；如果 Nord 浅色 chrome 不够明显，应在 Nord 色族内调整 chrome，而不是加回分割线。
- **迁移风险**：旧强调色用户会感知到变化；应保留明暗模式、字号、栏宽，并让紧凑主题选择成为明确的新入口。建议在发布说明中写清「强调色选择已由完整主题替代」。
- **实施建议**：本规格作为设计母票，实施时拆成四个阶段的可合并子票；每个阶段结束都更新对应截图与文档，避免最后一轮集中返工。
