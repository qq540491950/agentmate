## Problem Statement

作为 AgentMate 的用户，我在长任务里看不到一个可执行的计划：不知道当前做到哪一步、哪些步骤有依赖、完成标准是什么，也不知道还要消耗多少 token。模型或网络失败、应用崩溃、工具执行到一半后，我只能“重新生成”整轮；已经写过的文件、跑过的命令和做过的审批会全部重来，甚至可能重复产生副作用。

团队对话里，协调员把任务交给成员后，成员的回答往往就是最终回答；没有统一的计划、验收、证据和汇总。多个工具并行写同一个文件时没有工作区互斥，可能互相覆盖；MCP 或检索工具没有统一超时，可能把一回合永久挂住。

我还无法信任“已完成”：模型可以把计划步骤标成 completed，即使测试失败或文件没有写入；护栏只清洗界面上的流式文本，持久化事件、审计参数和标题仍可能保留密钥；一个回合失败后没有 trace 能还原模型调用、工具调用、审批和耗时。结果就是：任务能跑，但不可控、不可恢复、不可验证，也难以排障。

## Solution

把当前“单轮工具循环”升级为“可计划、可审批、可验证、可恢复、可审计、可限制成本”的 Agent 工作流，同时保留 ADK/Wails 架构和既有数据：

- 每个用户回合都有不可变的运行清单和持久化状态机；HITL、重试、分叉、崩溃恢复复用同一份清单，而不是重新读取当前配置。
- 所有工具经过统一网关：超时、并发、幂等、结果预算、审批、审计和稳定错误码；写文件具备原子性与乐观并发保护。
- 计划升级为带依赖、验收标准和证据的结构化计划；新增 `verify_work` 验证阶段，代码类任务只有测试/构建通过或用户显式豁免才可标记完成。
- 团队默认由协调员保持控制权，通过 `delegate_task` 委派成员、接收结构化结果、验收并汇总；旧 transfer 团队保留兼容模式。
- 护栏在持久化边界脱敏；AGENTS.md、Skill、文件、知识库和 MCP 输出按信任等级注入；工具结果超出预算时落盘为 artifact。
- 每个回合有检查点和 trace；失败可从中断步骤继续，取消后队列暂停，前端提供计划、审批、验证和运行详情面板。

这是一个母规格。实施按 P0 安全/失控、回合与验证、团队编排、观测与 UI 四批推进；详细工作包、依赖关系、测试矩阵和迁移方案见仓库中的执行方案。

## User Stories

1. 作为执行长任务的用户，我想让 Agent 先给出带依赖关系的简短计划，以便我知道它准备怎么做。
2. 作为执行长任务的用户，我想让每个计划步骤有明确的验收标准，以便“完成”不是模型的主观判断。
3. 作为执行长任务的用户，我想在会话头持续看到当前步骤、已完成数量和阻塞项，以便随时判断进度。
4. 作为执行长任务的用户，我想看到本回合的 token、费用和已用时间，以便评估是否继续。
5. 作为执行长任务的用户，我想在达到软预算时被暂停并选择“继续/停止”，以便长任务不会被硬杀，也不会无限烧钱。
6. 作为执行长任务的用户，我想让重复工具调用或团队互转触发环检测，以便错误提示词不会导致无限循环。
7. 作为执行长任务的用户，我想在模型或网络失败后从中断步骤继续，以便不用整轮重跑。
8. 作为执行长任务的用户，我想在应用崩溃后看到“恢复/查看变更/放弃”，以便决定如何处理半完成的回合。
9. 作为执行长任务的用户，我想让已成功执行的写文件操作在恢复时被识别并跳过，以便不会重复写入。
10. 作为执行长任务的用户，我想让 shell 和外部 MCP 调用在恢复时要求人工确认，以便不会自动重放有外部副作用的命令。
11. 作为执行长任务的用户，我想只重试失败的步骤，而不是重跑整轮，以便节省时间和 token。
12. 作为使用 HITL 的用户，我想让批准卡片显示文件 diff、命令风险和策略快照，以便我清楚自己在批准什么。
13. 作为使用 HITL 的用户，我想让恢复执行严格使用暂停时的 Agent、模型、工具和沙箱策略，以便暂停期间改配置不会改变已批准调用的权限。
14. 作为使用 HITL 的用户，我想让多个并行确认请求逐个处理，未处理的保持 pending，以便不会因为一次确认丢失其他调用。
15. 作为使用 HITL 的用户，我想让确认请求绑定到具体回合，以便旧卡片不能确认新回合的调用。
16. 作为使用 HITL 的用户，我想对同一类低风险操作做有作用域的批量授权，以便不必每次点击。
17. 作为团队成员的使用者，我想让协调员始终负责计划、验收和最终汇总，以便团队回答不是某个成员的半成品。
18. 作为团队成员的使用者，我想看到每个成员的工具调用和阶段进展，以便知道任务卡在哪里。
19. 作为团队成员的使用者，我想让成员只提交计划建议、由协调员单写计划，以便不会出现并发覆盖。
20. 作为团队成员的使用者，我想限制委派深度、同回合委派数量和单成员预算，以便团队不会指数级膨胀。
21. 作为使用文件工具的用户，我想让写入是原子的并保留原权限，以便中断不会留下半个文件。
22. 作为使用文件工具的用户，我想让写入/编辑携带读取时的哈希，以便外部修改不会被静默覆盖。
23. 作为使用文件工具的用户，我想让目录列表限制数量并跳过依赖/VCS 目录，以便大仓库不会挤爆上下文。
24. 作为使用文件工具的用户，我想让读取返回截断标记和下一页偏移，以便模型知道文件没有读完。
25. 作为使用 MCP 的用户，我想让每个 MCP 工具调用有超时和熔断，以便挂起的服务器不会拖死整个回合。
26. 作为使用并行工具的用户，我想让只读工具并行、写操作按工作区串行，以便速度和安全兼得。
27. 作为使用大工具结果的用户，我想让超出预算的结果落到 artifact 并返回摘要，以便上下文不会被单次输出占满。
28. 作为使用长上下文的用户，我想让压缩在回合内的安全边界发生，并保留当前计划、未决审批和最近证据，以便长任务不会在中途失败。
29. 作为代码任务的用户，我想让 Agent 在标记完成前运行测试/构建，以便“完成”有可验证的证据。
30. 作为代码任务的用户，我想在验证失败时让 Agent 自动修复有限轮次，以便常见错误能自愈。
31. 作为代码任务的用户，我想在验证仍失败时看到阻塞原因和输出 artifact，以便决定是否人工介入。
32. 作为关注隐私的用户，我想让密钥在会话历史、标题、审计和记忆中都被脱敏，以便护栏不是只做界面效果。
33. 作为关注提示注入的用户，我想让工作区文件、知识库和 MCP 输出被标记为不可信数据，以便模型不会把资料当指令。
34. 作为项目维护者，我想让 AGENTS.md、Skill 和用户提示的优先级在文档和测试中一致，以便不会出现“写的规则和实际注入顺序相反”。
35. 作为分叉会话的用户，我想让分支保留 todos、模型覆盖、推理级别和执行策略，以便分支不是“半套配置”。
36. 作为分叉会话的用户，我想在运行中不能分叉，以便不会得到半轮历史。
37. 作为排查问题的用户，我想按回合查看模型调用、工具调用、审批、重试、耗时和错误码，以便定位失败点。
38. 作为排查问题的用户，我想让 trace 默认脱敏并可开关，以便既能诊断又不会泄露密钥。
39. 作为使用取消的用户，我想在停止后让排队消息保持暂停，直到我点“继续队列”，以便“停止”真的停止。
40. 作为前端开发者，我想让聊天事件有版本号和显式类型，以便新增事件不会漏改历史渲染或导出。
41. 作为前端开发者，我想把事件 switch 抽成可测试的 reducer，以便乱序/重放/旧版本事件都有回归覆盖。
42. 作为维护者，我想让旧会话、旧团队和旧事件保持可读，以便升级不需要破坏性迁移。
43. 作为维护者，我想让每个工作包都有 fake SSE/httptest 测试和 `-race` 门禁，以便工作流改动不会引入并发回归。
44. 作为维护者，我想让这个母规格可以拆成 P0/P1/P2 子票，以便按依赖顺序交付。

## Implementation Decisions

- **回合生命周期**：引入 `TurnRecord`、`AgentSnapshot`、`TurnCheckpoint`、`PendingApproval`。每次发送、重新生成、确认恢复都先创建回合记录；状态为 queued、preparing、running、waiting_approval、verifying、completed、failed、cancelled、interrupted。状态迁移持久化并产生 `turn_state` 事件。
- **不可变运行清单**：回合开始时快照目标、供应商/模型、推理级别、系统提示哈希、工具清单、Skill/MCP 引用、工作区、审批策略、沙箱配置和计划版本。HITL、重试、恢复、分叉都复用该清单；配置热更新只影响下一个回合。
- **统一工具网关**：以现有工具运行时 ADR 为基础，建立 `ToolSpec` 注册表、Guard 管线、Executor、结果预算和审计。所有副作用工具声明效果、确认策略、超时、并发类别和幂等策略；注册时校验声明与行为。
- **工具预算与并发**：默认单次工具 120 秒（shell 保留 300 秒，验证命令可到 600 秒）；只读工具可并行，写文件/shell/验证按工作区互斥，`plan_todos` 按会话互斥；同一 MCP server 限制并发。结果超过 64KB 时落盘为 artifact，返回摘要、字节数和引用。
- **幂等与文件安全**：write/edit 接受读取时的 SHA-256（至少包含 mtime+size 的降级检查）；不匹配返回 `stale_file`。写入使用同目录临时文件、同步、重命名；保留已有权限，新建文件使用安全默认权限。
- **计划 v2**：计划步骤包含稳定 ID、标题、状态、依赖、验收标准和证据。状态为 pending、in_progress、blocked、completed、failed、skipped；同一会话最多一个 in_progress，步骤上限 50，禁止未知依赖和环。计划同时投影到 ADK session state 与持久化存储，团队只允许协调员写。
- **验证门禁**：新增 `verify_work` 工具/阶段，按项目类型检测测试、类型检查、构建命令，也允许项目配置自定义命令。失败结果回灌模型，最多自动修复 2 轮；仍失败则标 blocked，保留输出 artifact。代码类任务无验证证据不得完成；纯讨论任务可由用户显式豁免。
- **团队编排**：新增 `delegate_task`，协调员保持根节点，成员在子会话中运行；参数包含目标、上下文、约束、验收标准和返回结构。成员进度以成员作者转发到父时间线，结果为结构化 `DelegationResult`。支持并行只读委派、写操作按工作区分批串行；默认委派深度 2、同回合委派 8。旧 transfer 团队保留为兼容模式。
- **上下文与信任**：每次模型调用前估算上下文占用，在最近的安全工具边界做回合内压缩；保留当前目标、计划、未决审批、最近工具结果和文件引用。`@file`、知识库、MCP 和工具结果标记为不可信数据；AGENTS.md/Skill 标记来源，并明确不能覆盖安全、审批和沙箱规则。
- **持久化脱敏**：在 session service 外层增加脱敏装饰器，写入前清洗文本、工具参数和工具结果；标题、预览、审计和记忆使用同一清洗结果。需要保留原始敏感值的场景必须显式标记并写入受保护文件，而不是默认历史。
- **事件协议 v2**：`ChatStreamEvent` 增加版本、回合 ID、显式类型；新增 `turn_state`、`warning`、`retry`、`verification`、`plan`。前端的终止判断只看 `turn_state`，`warning` 不改变运行状态。旧事件继续兼容。
- **恢复**：每个模型响应后和每个工具批次后写检查点；启动时把没有活动运行句柄的 running 回合标记 interrupted。只读工具可重跑；write/edit 按前后哈希判断已应用/可重跑/需人工选择；shell 和外部 MCP 不自动重放。
- **分叉**：分叉等待活动运行结束或拒绝；复制 ADK session state（含 todos/plan）、模型覆盖、推理级别和执行策略；分支基线在事件复制完成后建立。
- **兼容与迁移**：配置新增字段全部可选并补默认值；数据库只增表/增列，旧会话按需惰性回填；旧团队保持 transfer 行为，新团队默认 delegate。默认软上限为单回合 200 次模型调用、120 次工具调用，达到时暂停询问而不是硬杀。

## Testing Decisions

- 好的测试只断言外部可观察行为：公共 RPC 返回值与错误、`chat:stream` 事件序列、SQLite 中的最终事件/状态、工作区文件最终内容、audit/trace 字段；不断言内部函数调用次数、私有结构或具体实现。
- **主测试缝**：`ChatService` 公共 RPC + `chat:stream` 事件流。用假 SSE 模型、临时 SQLite session、可控 clock 和真实临时工作区驱动；覆盖发送、确认、预算、计划、验证、恢复、取消、分叉。先例是现有 recording chat / fake SSE / event hook 测试。
- **工具测试缝**：复用现有 agentkit 工具构造器测试，不新增独立服务缝；直接断言超时、并发串行、原子写、stale hash、列表上限、结果落盘和审计字段。
- **前端测试缝**：优先复用现有浏览器桩和 `window.__emit` 事件注入；如果把聊天事件 switch 抽成纯 reducer，再新增一个 reducer 单测缝，不再增加第二个 DOM 缝。
- **状态机与失败路径**：覆盖所有状态迁移、`ev.ErrorCode` 阻塞、空响应、护栏 warning、所有终止路径都有 done/error、重复确认、跨回合确认拒绝、取消后队列暂停。
- **并发与恢复**：`-race` 下覆盖并发写同一文件、并发确认、并发取消、运行中分叉；崩溃恢复断言已应用的写不会重复，未应用的写可重跑，shell 需要人工确认。
- **团队**：协调员并行委派两个成员并汇总；成员失败返回协调员；委派深度/扇出限制；计划单写者。
- **上下文与脱敏**：5MB MCP 结果落盘、回合内压缩保留计划和未决审批、旧工具对不孤立、密钥不进入新会话/标题/审计/记忆。
- **先例**：现有 `chatservice_confirm_test`、`chatservice_fork_test`、`chatservice_sandboxmode_test`、`agentkit` 工具测试、前端 `chatUtils.test` 与浏览器桩。
- **门禁**：每个工作包通过 `go test ./internal/...`、`go test -race ./internal/...`、`go vet ./internal/... .`、前端 `tsc --noEmit`、`npm test`、`npm run build`；全量 `./scripts/verify.sh` 必须 `VERIFY: ALL GREEN`。

## Out of Scope

- 替换 ADK/Wails 或重写模型适配器。
- 云端任务队列、多用户账号体系、远端数据库同步。
- 为 stdio MCP 子进程补 OS 沙箱；本次只做调用超时、确认和审计。
- A2A 发布、鉴权、隔离工作区与远程调用链路；这块暂时保持现状，不在本次修改。
- Office 在线预览、网页运行预览、嵌套 AGENTS.md 发现。
- 供应商自动降级/模型回退链；单独评估。
- 一次性重写整个聊天页面；只抽出事件 reducer 和必要的工作流面板。
- 在本规格内直接实现所有工作包；母票先定义契约，子票按阶段实施。

## Further Notes

- 详细工作包、依赖关系、估算、迁移和风险见[执行方案](https://github.com/qq540491950/agentmate/blob/main/docs/specs/agent-workflow-upgrade.md)。
- 建议实施顺序：预算/工具网关/文件安全 → 回合状态机/HITL/计划验证/恢复 → 团队 `delegate_task` → trace/UI/评测。
- 总估算约 33–40 人日（含 20% 缓冲）；单人约 7–8 周，双人约 4–5 周。
- 这是母规格，可按执行方案中的工作包拆子票；子票必须引用本 issue，并遵守同一套 seams 与测试门禁。
- 当前只产出规格，未修改代码；A2A 相关内容暂缓。实施前先补 `docs/agents` 的 issue tracker/triage 配置，避免后续技能继续缺配置。
