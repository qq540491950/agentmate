# Spec：设置中心「通用」拆分为独立配置菜单

> 状态：本地规格（不发布 issue，按本地实现执行）。来源：2026-11-10 本地设计讨论。

## Problem Statement

用户进入设置中心后，「通用」同时承载外观、工作区、网络代理、长会话压缩、长期记忆和 A2A 服务六类设置。外观卡里还混有执行过程显示、自动朗读、智能会话命名、标题提炼模型和工具审计。用户需要在一个长页面里反复滚动才能找到某个设置，而且不同设置之间没有稳定的分类边界。

现有保存语义也与页面结构不匹配：主题和部分开关即时保存，工作区、代理和压缩参数依赖底部按钮，用户很难判断一次修改究竟有没有落盘。宽窗口下「通用」仍使用两列卡片网格，进一步放大了空白和阅读跳跃。

## Solution

- 删除「通用」，把其中的配置按任务心智拆成三个新的配置菜单：`外观与交互`、`对话与上下文`、`网络与服务`。
- 把「工作区目录」和「工具调用审计日志」迁入 `数据与存储`，与诊断、备份和工作区概念放在一起。
- 设置中心侧栏按 `基础设置` / `Agent 能力` / `数据与系统` 三组展示，组内设置项带图标；一级菜单仍为 11 项，默认进入 `外观与交互`，本轮不增加搜索或折叠分组。
- 五个配置页共享同一套显式保存：修改先保留在设置页草稿中，点底部「保存设置」后统一落盘；管理页继续即时增删改。
- 主题、明暗模式、字号和对话栏宽继续实时预览，但只有保存成功后才持久化和写入主题缓存。
- 返回、Esc、关闭设置以及任何会离开设置视图的全局快捷键，都经过同一套未保存守卫。
- 配置页改为单列纵向布局，用间距和表面层级组织内容，不增加布局级边框。

## User Stories

1. As a 桌面端用户, I want to 在设置侧栏直接看到「外观与交互」「对话与上下文」「网络与服务」三个独立入口, so that 我不必先进入「通用」再滚动寻找。
2. As a 首次打开设置的用户, I want to 默认落在「外观与交互」, so that 最常见的主题与阅读偏好一步可达。
3. As a 用户, I want to 在「外观与交互」里只看到主题、明暗模式、字号、对话栏宽、执行过程显示和自动朗读, so that 视觉与交互偏好不会被网络或存储设置打断。
4. As a 用户, I want to 在「对话与上下文」里集中管理智能会话命名、标题提炼模型、上下文压缩和长期记忆, so that 所有影响会话行为的设置在一个稳定位置。
5. As a 用户, I want to 在「网络与服务」里同时配置 HTTP 代理和 A2A 服务, so that 出站连接与对外服务不必在页面两端寻找。
6. As a 用户, I want to 在「数据与存储」里看到工作区目录, so that 文件落点与备份、诊断、存储管理处于同一语义区域。
7. As a 用户, I want to 在「数据与存储」的诊断卡里看到工具调用审计开关, so that 开关和审计日志查看入口相邻。
8. As a 用户, I want to 侧栏按 `基础设置` / `Agent 能力` / `数据与系统` 分组并显示图标, so that 长菜单也能快速扫到目标配置。
9. As a 用户, I want to 在新的配置页上看到单列卡片, so that 阅读顺序稳定且宽窗口不再出现大片空白列。
10. As a 用户, I want to 无修改时看到禁用的「保存设置」, so that 我知道当前没有待提交内容。
11. As a 用户, I want to 有修改时看到可用的「保存设置」, so that 提交点唯一且明确。
12. As a 用户, I want to 在五个配置页之间切换时保留草稿, so that 可以跨页调整后再一次性提交。
13. As a 用户, I want to 在任意配置页保存时提交全部待保存设置, so that 不需要记住最后一次修改发生在哪一页。
14. As a 用户, I want to 只在五个配置页看到统一保存条, so that 模型供应商、Agents、团队、Skills 和 MCP 的即时保存逻辑不会被第二个保存按钮干扰。
15. As a 用户, I want to 修改主题后立即看到预览, so that 调色不需要先保存再观察。
16. As a 用户, I want to 未保存就放弃时恢复已保存主题, so that 预览不会意外改变下一次启动的外观。
17. As a 用户, I want to 主题保存成功后才更新本地主题缓存, so that 未保存主题不会在下次启动首帧闪现。
18. As a 用户, I want to 自动命名、自动记忆和 A2A 自动启动也等待统一保存, so that 不再出现部分开关已落盘、另一部分仍待保存的混合状态。
19. As a 用户, I want to 返回、Esc 或关闭设置时若有未保存修改看到「保存并退出 / 放弃修改 / 继续编辑」, so that 离开路径不会静默丢失草稿。
20. As a 用户, I want to 从设置页使用全局快捷键离开时也触发同一未保存守卫, so that ⌘N、⌘K、⌘F、⌘B 和会话切换不会绕过保护。
21. As a 用户, I want to 选择「保存并退出」后先完成保存再离开, so that 保存失败时仍停留在设置页并看到错误。
22. As a 用户, I want to 选择「放弃修改」后恢复外观预览并丢弃草稿, so that 页面状态与已保存配置一致。
23. As a 用户, I want to 选择「继续编辑」后关闭提示并保留草稿, so that 我可以修正未完成输入。
24. As a 用户, I want to 开启 A2A 自动启动但未选择 Agent 或端口非法时，保存被阻止, so that 下次启动不会以半配置状态失败。
25. As a 用户, I want to A2A 保存校验失败时自动切到「网络与服务」, so that 我知道该修正哪个字段。
26. As a 键盘用户, I want to 保存按钮、侧栏菜单和离开确认对话框都可通过键盘操作, so that 设置中心保持可访问。
27. As a 用户, I want to 通过模型选择器、@ 浮层或空状态直达设置时仍落到正确菜单, so that 现有快捷入口不被信息架构调整破坏。
28. As a 维护者, I want to 设置菜单顺序、默认入口和配置页判定由同一份纯数据驱动, so that 新增或删除菜单时不会多处漏改。
29. As a 维护者, I want to 未保存判定只比较草稿与已保存快照, so that 用户改回原值时 dirty 状态自动消失。
30. As a 回归测试者, I want to 用纯函数测试菜单模型、dirty 判定和 A2A 校验, so that 这些规则不依赖浏览器渲染。
31. As a 回归测试者, I want to 用浏览器桩走查 11 个菜单、五个保存页、单列布局和离开确认, so that 页面级交互仍按真实 UI 验证。

## Implementation Decisions

- **一级菜单模型**：设置菜单统一为 `appearance`、`conversation`、`models`、`network`、`agents`、`teams`、`skills`、`mcp`、`knowledge`、`data`、`about`，对应中文标签为「外观与交互」「对话与上下文」「模型供应商」「网络与服务」「Agents」「Agent 团队」「Skills」「MCP 服务」「知识库」「数据与存储」「关于」。
- **导航分组**：`基础设置` 包含外观与交互、对话与上下文、模型供应商、网络与服务；`Agent 能力` 包含 Agents、Agent 团队、Skills、MCP 服务；`数据与系统` 包含知识库、数据与存储、关于。组标题使用 12px 弱化文字，设置项使用 16px 图标；选中态继续使用 `accent-soft` + `accent-text`，不增加左侧竖条。
- **默认与兼容**：默认菜单为 `appearance`；旧的 `general` 标识按 `appearance` 处理，避免内部旧入口打开空白页。`SettingsTab` 类型由设置模型模块导出，现有页面继续复用。
- **删除「通用」**：不再存在 `general` 菜单键；其内容按以下边界迁移，不新增设置项，不改变默认值。
- **外观与交互**：`外观` 卡包含主题、明暗模式、正文字号、对话栏宽；`交互` 卡包含执行过程显示、自动朗读回复。
- **对话与上下文**：`会话` 卡包含智能会话命名、标题提炼模型；`上下文压缩` 卡包含滑动窗口压缩间隔和上下文占用阈值（%）；`长期记忆` 卡包含自动存入、记忆统计和清空操作。
- **网络与服务**：`网络` 卡包含 HTTP 代理；`A2A 服务` 卡包含发布 Agent、端口、启动/停止、运行状态和开机自动启动。
- **数据与存储**：新增 `工作区` 卡承载全局工作区目录；`诊断` 卡加入工具调用审计开关；`备份与迁移` 保持不变。
- **布局**：新拆出的三个配置页与 `数据与存储` 使用单列内容，最大宽度约 896px；`知识库` 保持现有单列宽度；管理页继续使用现有 `PageShell` 布局。
- **保存范围**：`外观与交互`、`对话与上下文`、`网络与服务`、`知识库`、`数据与存储` 共用同一个保存条和 dirty 状态。模型供应商、Agents、Agent 团队、Skills、MCP 服务继续在自身页面即时保存；`关于` 不显示保存条。
- **草稿模型**：页面加载时同时保存「已保存快照」和「当前草稿」。菜单切换只改变当前菜单，不提交、不重置草稿。保存成功后才用草稿替换快照并清除 dirty。
- **dirty 判定**：比较草稿与已保存快照的完整设置对象；用户把字段改回原值时 dirty 应自动消失。无快照或仍在加载时不显示可保存状态。
- **主题预览**：主题预设、明暗模式、字号和对话栏宽在草稿变更时立即应用到根界面；保存前不调用主题缓存写入，也不调用后端。放弃或保存失败时以已保存快照重新应用外观。
- **移除即时保存例外**：主题与明暗模式不再单独保存；智能会话命名、自动记忆、A2A 自动启动不再在开关变更时单独调用保存接口。所有配置统一等待显式保存。
- **保存条状态**：无 dirty 或正在保存时禁用；保存失败保留 dirty 并显示错误 toast；保存成功显示成功 toast 并更新快照。
- **A2A 表单归入设置草稿**：发布的 Agent、端口与自动启动开关作为设置对象的一部分参与 dirty 比较；发布/停止操作仍即时调用 A2A 服务，不等待设置保存。
- **A2A 保存校验**：仅当自动启动开启时校验。未选择 Agent 或端口不是 1–65535 的整数时阻止保存，切换到 `网络与服务` 并显示具体错误。关闭自动启动时不因端口输入阻止其他配置保存。
- **离开守卫**：设置页对外注册一个统一的离开守卫。返回按钮、Esc、设置视图关闭以及 App 层会切回对话的全局快捷键都先将目标动作交给该守卫；无 dirty 时直接执行，有 dirty 时打开三选一 Dialog。
- **离开 Dialog**：提供「保存并退出」「放弃修改」「继续编辑」。保存并退出先调用保存，成功后才执行离开动作；失败则保留 Dialog 关闭后的当前页和 dirty 状态。放弃修改先恢复已保存外观和草稿，再执行离开动作。继续编辑只关闭 Dialog。
- **全局快捷键**：App 层持有离开守卫引用；⌘N、⌘K、⌘F、⌘B、上一个/下一个会话等会离开设置视图的快捷键统一经过守卫，守卫完成后才执行原快捷键动作。
- **深链接**：没有指定菜单时进入 `appearance`；现有模型选择器、@ 浮层、会话头徽标和空状态传入的 `models`、`agents`、`teams` 等键保持有效。
- **无后端契约变更**：设置 schema、默认值、归一化、导出脱敏和 Wails 绑定均不变；本轮只调整前端信息架构与保存交互。
- **视觉契约**：设置导航、卡片和行继续遵守 Nord 表面契约；不增加布局级 border/ring，不用左竖条表示选中，不在组件里写死颜色。

## Testing Decisions

- 好的测试只验证外部行为：菜单顺序与默认入口、配置页判定、dirty 判定、A2A 校验结果，以及浏览器中真实渲染后的导航、保存条、Dialog 和布局。不断言 React 内部 state 名称、组件树层级或具体事件实现。
- **纯函数测试**：新增设置模型模块，集中导出菜单定义、默认菜单、配置页判定、`Settings` 草稿与已保存快照的 dirty 比较、A2A 自动启动校验。用 Vitest 表驱动测试；先例为现有主题解析测试和执行过程显示测试。
- **纯函数覆盖范围**：菜单数量和顺序、`general` 兼容、配置页/管理页/关于页分类、所有设置字段的 dirty 变化与改回原值、A2A 自动启动关闭时不校验、缺少 Agent、端口为非整数/越界/合法值。
- **浏览器桩验证**：复用 `npm run stub`，走查 11 个菜单、五个配置页保存条、管理页不出现保存条、单列布局、主题预览与放弃回滚、三选一 Dialog、保存失败停留、A2A 校验失败切页。先例为现有设置页视觉走查与迭代日志中的几何测量。
- **不新增组件测试设施**：当前前端测试栈没有 jsdom/Testing Library；本轮不引入 RTL、jsdom 或 Playwright。`SettingsPage` 组件只做编排与渲染，页面级行为由浏览器桩承担。
- **后端测试**：没有 Go schema 或 API 变更，不新增后端测试；现有 `SaveSettings` 与 A2A 服务测试继续作为回归防线。
- **提交前验证**：前端类型检查、Vitest、生产构建全绿；浏览器桩完成深/浅主题与宽窄视口走查。

## Out of Scope

- 发布到 issue tracker、交给远端修复流水线或创建 GitHub issue。
- 设置搜索、命令面板设置检索、分组折叠/展开、自定义分组顺序。
- 新增设置项、删除低频设置、改变设置默认值或重写现有说明文案。
- 重做控件视觉、主题系统、字体、间距令牌或管理页布局。
- 设置 schema、Go 配置结构、Wails 绑定、导出脱敏或后端 API 变更。
- 原生窗口关闭、系统关机或进程退出时的未保存保护；本轮只覆盖设置视图内的离开路径。
- 移动端/窄窗口响应式重构、多语言、设置多窗口化。
- `知识库` 的文件创建、删除、检索测试等即时操作改为等待保存；这些操作保持现状。

## Further Notes

- **关键风险一：全局快捷键绕过守卫**。如果只处理返回按钮和 Esc，⌘N/⌘K/⌘F/⌘B 会直接切回对话并丢失草稿。实现必须把 App 层离开设置的动作也交给同一守卫。
- **关键风险二：主题缓存污染**。实时预览只能调用根界面应用逻辑；本地主题缓存必须在保存成功后写入，否则放弃修改后下次启动会先闪现未保存主题。
- **关键风险三：隐藏的 A2A 校验阻塞全局保存**。A2A 自动启动开启但表单不完整时，用户可能在另一配置页点保存；失败后必须自动切到 `网络与服务`，否则错误不可定位。
- **关键风险四：知识库与管理页语义混淆**。知识库的嵌入配置属于共享保存，但知识文件操作是即时动作；管理页完全即时保存。保存条只在五个配置页出现，避免双重提交入口。
- **实施顺序建议**：先建立菜单与草稿纯模型并测试；再改设置页导航与卡片归属；随后接入共享保存、离开守卫和 A2A 校验；最后更新浏览器桩夹具并完成视觉走查。
- **完成标准**：侧栏不存在「通用」，11 个菜单按三组可达且带图标；旧「通用」所有设置无遗漏；五个配置页共享 dirty 状态；返回/Esc/全局快捷键都触发三选一 Dialog；主题放弃回滚；A2A 保存失败定位到「网络与服务」；类型检查、测试和构建通过。
