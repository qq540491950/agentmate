# 运行时代理自动加载 AGENTS.md 作为系统约束

运行时代理的约束此前只有用户配置的系统提示词，以及 /skill、@文件 两类按轮注入；编码代理生态的 AGENTS.md 约定在产品内完全缺席——同一份文件在 Codex 等编码代理里被自动遵循，在 AgentMate 里却不生效。我们决定：所有本地代理（直连助手、配置 Agent、团队负责人与成员）装配基础系统指令时自动叠加两份工程指南——用户主目录 `~/.agents/AGENTS.md`（全局）与当前会话有效工作区根目录的 `AGENTS.md`；全局在前、工作区在后，冲突以后注入的为准。文件缺失或不可读时跳过，不阻塞会话。远程 A2A 代理没有本地指令提供方，天然排除。

## 当前范围

**不做嵌套发现。** AGENTS.md 标准的「嵌套文件就近覆盖」为 monorepo 设计，锚点是「正在编辑的文件」；AgentMate 的工作区是会话级单任务目录，没有对应锚点。v1 只读上述两处，是对标准的有意简化，出现嵌套场景需求再评估。

**不设大小上限。** Codex CLI（默认 32KB）与 Claude Code（约 30KB）对超大指令文件默认静默截断，社区将其视为缺陷（openai/codex#13386）。我们全文注入，仅当单份超过 48KB（与 @文件单文件上限同源）时在该块末尾追加中文警告（体积 + 上下文挤占提示）——比行业现状既不丢内容、也不静默。

## 后果

- 工程指南与用户系统提示词、技能正文共存：装配顺序为角色提示词 → 工程指南 → 技能正文，后文为准，用户提示词里的显式要求仍可覆盖指南。
- v1 无设置项与 UI：强制生效，豁免的唯一方式是删除或重命名文件；超大文件的警告只进入指令上下文，不新增界面元素。
- 工作区根的解析唯一入口是会话的有效工作区（首轮锁定、项目会话解析到项目根），因此分叉与绑定项目的会话各取所需。
