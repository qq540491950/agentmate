## 原文

### Problem Statement

作为 WorkBuddy Agent 的用户，我目前无法把“一个对话”当成一个可验收的工作任务来管理：所有会话共用设置页中的同一个工作区，新会话不能选择自己的目录；并行任务写入同名文件时会互相覆盖；产物只散落在聊天里的工具卡中，离开某条消息后很难再次找到；我也看不到任务期间新增、修改或删除了哪些文件。

这会让本地 Agent 的“执行结果”难以被信任和交付。对话看起来完成了，但我仍需要自己到文件系统里猜文件在哪里、是否完整、是否误改了别的文件；一旦同时运行两个任务，文件边界和变更归属也会变得不可靠。

### Solution

把每个新建会话升级为一个有独立工作目录的任务，并在对话页提供可收起的右侧结果区：

- 新任务默认自动获得独立目录，也可以在开始前选择已有文件夹。
- 会话绑定工作区后，文件读写工具、提示词中的工作区变量与产物预览都使用该任务的工作区。
- 右侧结果区提供「产物 / 全部文件 / 变更」三个视图：查看本次任务生成或修改的文件、浏览任务目录、核对新增/修改/删除的文件。
- 点击文件可复用现有预览能力查看图片、PDF、Markdown 与文本；不支持的格式仍显示元数据。
- 切换、并行、重启或分叉会话时，文件隔离与变更归属保持可预测。
- 现有会话继续以全局工作区回落运行，不破坏历史数据。

用户完成一轮任务后，不需要翻聊天记录或手动找目录，就能在右侧确认“交付了什么、文件在哪里、这次任务改了什么”。

### User Stories

### Implementation Decisions

#### 1. 任务与工作区模型

- 会话元数据新增 `WorkspaceDir`，保存规范化后的绝对路径。
- 新增唯一的“有效工作区”解析规则：会话显式路径优先；没有显式路径时回落到全局工作区。运行、文件工具、提示词工作区变量和产物预览必须全部复用该规则。
- 新建会话的 API 接受可选工作目录：
  - 传空字符串时，在全局工作区下创建唯一的任务子目录，并把该路径写回会话。
  - 传入用户选择目录时，验证为存在的绝对目录、可读且可写，再持久化规范化路径。
- 任务工作区在首轮执行前可通过会话服务更换；首轮事件产生后视为锁定，拒绝后续更改。该限制用于保证历史、变更基线和文件验收的对应关系。
- 新建任务选择显式目录时，如该规范化路径已被另一个未归档任务占用，直接拒绝并提示已有任务；用户必须另选目录或归档旧任务。自动创建的目录天然唯一。旧会话的全局工作区回落不参与此冲突检查。
- 旧会话的 `WorkspaceDir` 为空，按回落规则继续使用全局工作区，不做批量目录迁移。旧会话首次请求任务快照时懒建立基线，此后按新任务同样规则显示累计变化。
- 分叉会话继承源会话的“有效工作区”路径，但在分叉时建立新的变更基线；不复制目录内容。
- 归档与会话删除只处理元数据和事件，不递归删除任务工作区。实现与 UI 文案都要明确这一点。

#### 2. Agent 运行时与路径边界

- Agent 构建入口接收本次会话的有效工作区，而不是直接读取全局设置。
- 内置文件工具、`{{workspace}}` 提示词变量和任务文件预览使用会话工作区。
- 知识库、Skills 物化、会话导出等应用级资源继续使用全局工作区，不随任务切换。
- 所有路径仍通过现有安全路径解析器校验；任务目录、预览目标与快照扫描都不得跟随符号链接逃逸。
- 运行期间 HITL 确认协议不变；批准写入后，结果区查询应能发现对应文件变化。

#### 3. 任务产物快照与变更基线

- 在 Artifact 服务中增加会话级快照契约，一次返回：
  - 当前任务的产物列表；
  - 当前工作区文件列表；
  - 相对基线的新增/修改/删除清单；
  - 基线时间、刷新时间、扫描是否截断等快照状态。运行中状态继续复用现有会话运行表，不新增后端耦合。
- 产物定义为任务开始后新增或被修改的常规文件；删除文件只出现在变更清单。
- 快照基线在会话创建时建立并持久化，使用独立于会话数据库的应用数据文件，按会话 ID 原子写入；不修改会话数据库 schema，也不引入第二个 SQLite 写连接。
- 变更判断以文件是否存在、大小和修改时间为主，不读取全文件内容做哈希；文件级变更用于验收，不承诺取证级完整性。
- 每轮完成、切换到该会话、HITL 批准后的相关工具结果、以及用户手动刷新时重新扫描。
- 删除会话时清理对应快照元数据，但保留任务文件和目录。
- 扫描规则：
  - 只统计普通文件，不跟随符号链接。
  - 跳过应用内部导出、版本库元数据、隐藏文件/目录、常见依赖缓存与虚拟环境目录。
  - 扫描数量设置硬上限；超过上限时仍返回已扫描结果并标记截断，不阻塞聊天。
  - 展示列表可继续按现有 200 条窗口限制，但汇总计数应反映截断前的已发现总数。
- 预览继续沿用现有安全上限：图片/PDF 最大 12 MB，文本最大 512 KB 并标记截断；二进制内容不做 UTF-8 预览。

#### 4. Wails 服务契约

- 会话创建方法新增工作目录入参；前端空值表示自动创建独立任务目录。
- 新增会话工作区更新方法，仅允许在首轮执行前调用。
- Artifact 服务新增会话级快照方法，以及按会话 ID 打开文件预览的方法；现有全局预览方法保留，供知识库预览使用。
- 快照返回稳定的结构化模型，不向前端暴露绝对工作区路径以外的内部快照文件位置。
- Go 服务变更后必须重新生成 Wails TypeScript 绑定；前端只使用生成绑定，不手改生成文件。

#### 5. 聊天页交互

- 新建对话对话框在 Agent/团队/远程选择之后增加“任务工作目录”控件：
  - 默认选项为“自动创建独立目录”。
  - 提供“选择文件夹”按钮，调用原生目录选择器。
  - 选择后显示完整路径，并提供恢复自动目录的重置操作。
  - 创建失败时保留表单状态并显示中文错误。
- 会话标题栏显示工作区状态入口和结果区开关；运行中或扫描中提供明确状态。
- 结果区包含「产物 / 全部文件 / 变更」标签：
  - 产物：状态徽标、名称、相对路径、大小、更新时间、预览操作。
  - 全部文件：按路径搜索的文件列表，点击预览。
  - 变更：新增/修改/删除筛选与计数，删除项不可预览但保留路径和时间。
- 结果区为空、加载、错误、截断和运行中均有独立状态，不与聊天消息混用。
- 桌面宽度下结果区作为第三栏并可收起；窄屏下使用覆盖式面板。开关和标签满足键盘与 ARIA 要求。
- 结果区请求带会话 ID 和请求代次保护；快速切换会话时，迟到响应不得覆盖当前会话。
- 工具卡预览改为会话级预览；`search_knowledge` 返回的引用继续走应用级预览，避免知识库文件预览回归。
- 任务运行完成事件触发结果区刷新；刷新失败只提示结果区错误，不影响已完成的聊天回合。

#### 6. 兼容与失败处理

- 旧会话不需要迁移即可打开；其有效工作区为空目录、不可读或不存在时，聊天仍可打开并显示可操作错误。
- 自动任务目录创建失败时，新会话创建失败，不留下半创建会话元数据。
- 用户选择目录成功但快照基线建立失败时，会话创建失败并清理会话元数据；绝不删除用户选择的目录。只有应用自动创建且仍为空的目录才能回滚删除，不进入“有会话但无法验收”的半状态。
- 快照扫描错误不改变 Agent 回合结果，不阻止后续继续对话。
- 分叉、归档、重命名、模型覆盖等现有会话元数据路径继续统一走现有元数据变更机制。

### Testing Decisions

- 好的测试只断言外部可观察行为：服务返回值、事件流、磁盘上的最终文件状态、快照结果、UI 中用户可见状态；不断言私有扫描函数调用次数或内部数据结构布局。
- **最高测试接缝一：Wails 服务契约。** 通过现有会话/Artifact 服务的公开方法，在临时目录和假 SSE 模型服务器上验证完整任务行为。优先复用该接缝，不新增内部扫描器测试缝。
- **最高测试接缝二：浏览器桩。** 使用真实聊天页、现有 `setTransport` 数据和事件注入，验证右侧面板、标签切换、空/错/截断态、会话切换与预览请求。该缝已有视觉回归先例。
- 后端任务隔离：
  - 新建两个会话并让它们写同名相对路径，断言磁盘上落在两个不同目录。
  - 断言会话 A 的快照不包含会话 B 的文件。
  - 断言旧会话空工作区回落到全局工作区，并在首次快照时懒建立基线。
  - 断言显式目录已被另一个活动任务占用时创建被拒绝；归档旧任务后可复用。
- 后端运行时：
  - 使用 fake SSE 模型触发内置写文件工具，断言文件落在会话工作区而非全局工作区。
  - 断言提示词变量解析使用会话工作区。
  - 保留 HITL 写文件测试并扩展断言：批准后快照能识别该文件，拒绝后不产生变更。
- 后端快照：
  - 建立基线后依次新增、修改、删除文件，断言三种状态、计数和列表顺序。
  - 重启服务实例后再次读取，断言基线与绑定仍然存在。
  - 超出数量上限时断言截断标志与已发现计数。
  - 目录穿越、符号链接逃逸、隐藏目录、版本库元数据和依赖目录不进入结果。
  - 删除会话后断言快照元数据被清理但任务文件仍在；用户选择的目录在任何失败路径都不会被删除。
  - 分叉后源任务与分支的后续变更互不混淆。
- 后端预览：
  - 会话级预览只能打开该任务目录内的文件。
  - 知识库全局预览继续可用。
  - 大文本截断与超大二进制拒绝沿用现有行为测试。
- 并发：
  - 并行会话同时写文件和读取快照，配合 `-race` 断言无数据竞争、无跨目录串数据。
- 前端：
  - 浏览器桩新增任务快照和会话级预览处理器，验证右侧面板展开/收起、三标签、搜索、空态、错误态、截断提示与会话切换。
  - 对快照摘要、变更排序、路径搜索等纯函数使用 vitest；先例是现有 chatUtils 与 mcpEnv 单测。
  - 验证桌面三栏布局和窄屏覆盖式布局，深色与浅色主题都包含在视觉走查中。
- 质量门：
  - 后端全量测试与 race；
  - 前端类型检查、vitest、构建；
  - 浏览器桩视觉回归；
  - Wails 绑定再生成与生产构建；
  - 最终执行仓库的一键验证脚本。

### Out of Scope

- 行级 diff、三方合并、回滚与文件恢复。
- Office、PPT、Excel、HTML 浏览器预览或外部默认应用打开。
- 实时文件系统 watcher；本轮采用回合结束、切换、批准和手动刷新触发扫描。
- 为每个任务复制知识库、Skills 或独立导出目录。
- 远程 A2A 任务与本机任务之间的工作区同步。
- 分叉时复制整个工作区。
- 删除会话时清理工作区文件。
- 项目/空间分组、任务状态筛选、批量归档与批量删除。
- 任务或产物分享、云同步、资料库。
- IM 远程控制、定时任务和技能市场。
- OS 级沙箱、完整访问权限档位与更细粒度命令审批。
- 将任务元数据从配置文件迁移到 SQLite。

### Further Notes

- MCP 调研依据：
  - WorkBuddy 官方「结果查看」将右侧结果区定义为产物、全部文件、变更和预览的统一验收位置：https://www.workbuddy.ai/docs/zh/workbuddy/Results
  - WorkBuddy 官方「快速开始」明确每个任务可选择工作目录，并说明右侧结果区与多任务并行：https://www.workbuddy.ai/docs/zh/workbuddy/Quickstart
  - WorkBuddy 官方更新日志持续优化任务与产物分享、文件预览性能、产物统计与预览浮层，说明“可验收的产物工作台”是产品主线：https://www.workbuddy.ai/docs/zh/workbuddy/Changelog
- 本规格优先实现前三类结果：产物、全部文件、文件级变更；网页/浏览器预览与行级 diff 后续独立迭代。
- 兼容策略坚持“新会话隔离、旧会话回落”：不自动移动任何用户文件，不因升级改变既有会话的可打开性。
- 结果区不是权限系统。任务工作区只解决文件边界与验收可见性，HITL 与安全路径校验仍是写操作安全的核心。
- 实施时按仓库约定在迭代日志顶部追加本轮记录，提交使用约定式前缀，并在说明中列出测试证据。
