## 原文

### Problem Statement

作为 WorkBuddy Agent 的用户，我在 Windows 上无法完成 MCP 服务器的 OAuth 授权（浏览器打开的授权地址被截断）；我配置了系统环境变量代理却被应用无视，而一旦填写应用内代理，连本地 Ollama / 本地 MCP 的回环流量也被推进代理；我在多个会话并行使用时，重新生成或删除会话偶发出现历史"复活"或半截时间线；我删除了知识库目录后语义检索仍在返回已删除文件的内容；我在工作区放了一个大文件后，让 Agent 读文件或预览产物会把整个应用内存撑爆；我从朋友那里导入一个分享的 Agent 后，每一轮对话都直接报错，完全不可用。

此外，作为开发者，验证脚本在 Windows 上无法全绿：5 个测试失败（权限断言与数据库句柄泄漏导致的临时目录清理失败），"ALL GREEN" 的质量承诺只在 macOS 上成立。

### Solution

对代码审查发现的 3 个高危问题与 6 个确定性缺陷做一轮集中加固，使应用在 Windows / macOS 双平台上行为一致、可验证：

- MCP OAuth 授权在任何平台都能正确唤起浏览器并携带完整授权 URL。
- 全局代理只在用户显式配置时生效，空配置回落系统环境变量代理，且本机回环流量永远直连。
- 会话历史的破坏性操作（重新生成 / 编辑重发 / 删除）先等旧一轮真正退出，再动存储，杜绝竞态复活。
- 知识库目录删除后索引同步清空；嵌入部分失败时保留已成功的结果并报告失败清单。
- 工作区读取（文件工具与产物预览）改为有界流式读取，写入增加大小上限，单个大文件不再威胁进程内存。
- Agent 分享导入自动清洗悬空的技能 / MCP 引用并明确告知用户；技能导入与物化目录命名使用同一套规范化规则，不再互相覆盖。
- 测试套件在 Windows 与 macOS 上同样全绿：测试内数据库句柄一律显式关闭，权限断言只在 POSIX 语义平台启用。

### User Stories

1. 作为 Windows 用户，我想让 MCP OAuth 授权链接完整地在我的默认浏览器中打开，以便我能一次性完成第三方服务的登录授权。
2. 作为使用企业代理的 Windows 用户，我想让授权回调可靠地回到应用的本地监听端口，以便授权流程不会因为浏览器侧报错而中断。
3. 作为依赖 HTTP_PROXY / HTTPS_PROXY 环境变量上网的用户，我想让应用在没有配置应用内代理时遵循我的环境变量，以便访问境内外模型服务不需要额外配置。
4. 作为本地 Ollama / 本地 MCP 用户，我想让发往 127.0.0.1 与 localhost 的请求始终直连，以便回环流量不被代理转发导致连接失败或隐私外泄。
5. 作为配置了应用内代理的用户，我想让模型、嵌入、MCP、A2A 的出站流量统一走代理，以便一处配置全局生效（保持现有行为）。
6. 作为并行使用多个会话的用户，我想让重新生成或删除会话时后台正在运行的旧一轮先被终止并完全落定，以便历史不会被删除后又被重新写入。
7. 作为编辑后重发消息的用户，我想让被替换的那一轮对话干净地消失，以便时间线上不会留下旧轮次的残片。
8. 作为删除会话的用户，我想让会话及其全部事件被彻底移除，以便已删除的会话不会通过搜索或分叉"复活"。
9. 作为知识库维护者，我想让删除整个 knowledge 目录后语义索引同步清空，以便搜索不再返回已删除文件的内容。
10. 作为知识库维护者，我想让某个文件嵌入失败时其他文件的成果被保留，以便一次网络抖动不会让整库重建从头再来。
11. 作为知识库维护者，我想在重建结束后看到失败文件的清单，以便只针对失败项排查网络或配额问题。
12. 作为让 Agent 读取工作区文件的用户，我想让文件读取在达到上限后停止并明确标记截断，以便一个 2GB 的日志文件不会拖垮应用。
13. 作为预览工作区产物的用户，我想让大文件的预览有内存上限，以便浏览产物列表和预览详情始终保持流畅。
14. 作为配置了写文件工具的用户，我想让模型单次写入的内容有大小上限，以便失控的生成不会把磁盘写满。
15. 作为导入他人分享 Agent 的用户，我想让导入时悬空的技能与 MCP 引用被自动清除并收到提示，以便导入的 Agent 开箱即用而不是每轮报错。
16. 作为导出 Agent 分享的用户，我想让分享文件里只携带接收方能解析的引用，以便对方导入后不会踩到同样的报错。
17. 作为导入中文名技能的用户，我想让两个规范化后同名的技能在导入时被识别为冲突，以便它们不再互相覆盖对方的物化文件。
18. 作为使用长期记忆的用户，我想让包含 % 或 _ 的记忆查询按字面匹配，以便搜索结果符合直觉且与会话搜索行为一致。
19. 作为挂载了 stdio MCP 服务器的用户，我想让应用退出时子进程随之退出，以便系统里不留孤儿进程。
20. 作为在 Windows 上开发本项目的开发者，我想让全部测试在 Windows 上通过，以便 verify.sh 的"ALL GREEN"承诺在两个平台都成立。
21. 作为开发者，我想让每个测试结束时关闭自己打开的数据库连接，以便临时目录清理不再因句柄占用而失败。
22. 作为开发者，我想让文件权限断言只在支持 POSIX 权限的平台上运行，以便 Windows CI 不再出现必然失败的用例。
23. 作为跨平台用户，我想让 macOS 上的一切现有行为保持不变，以便本次加固对已有用户零回归。
24. 作为运维者，我想让应用日志记录代理回落与导入清洗等关键决策，以便排查配置问题时有一手证据。

### Implementation Decisions

- **MCP 认证层**：将「按平台构造浏览器启动命令」提取为可独立测试的纯函数；Windows 分支不再把裸 URL 交给 cmd 解析（改用不经过 shell 二次解析的启动方式，或先补空标题引号），macOS / Linux 分支保持现状。全局可注入的 URLOpener 出口保持不变。
- **全局代理模块**：空代理时回落 ProxyFromEnvironment 而不是禁用；代理函数对 loopback 地址（127.0.0.1、localhost、::1）返回直连。保留「仅启动时应用一次、修改需重启」的现有契约与 UI 文案。
- **会话引擎**：运行句柄在释放时关闭一个完成信号；重新生成 / 编辑重发 / 删除会话在取消旧轮后等待该信号（带数秒超时兜底）再裁剪或删除事件。运行登记的指针身份语义保持不变。
- **知识索引**：目录不存在视为空库并清除全部陈旧行；重建结束后写入成功文件的行，失败文件聚合成清单随错误返回；mtime 增量与换模型全量重建逻辑不变。
- **工作区文件工具与产物预览**：读取路径改为按上限流式读取（到上限即停并追加截断标记），不再整文件载入内存；写入工具新增单次内容大小上限（与图片附件上限同量级），超限返回明确错误。
- **配置服务（导入）**：Agent 分享导入时校验 SkillIDs 与 MCPServerIDs，悬空引用直接剥离；导入结果附带被剥离项的警告列表（API 契约变化：导入返回结构新增警告字段，前端 toast 展示；Wails 绑定再生成）。
- **配置服务（技能）**：工作区技能导入的去重键与「物化目录名」统一为同一个规范化函数；规范化后同名的技能导入时报冲突并跳过，与手动保存的行为一致。
- **记忆服务**：LIKE 查询与模糊字符转义采用与会话搜索相同的 ESCAPE 策略。
- **MCP 管理器**：新增全量断开入口，逐个关闭受控传输并清理状态；应用关闭钩子中调用（幂等，重复调用安全）。
- **测试基建**：测试用的会话库构造函数统一注册关闭清理；文件权限断言加平台条件（仅 POSIX 语义平台执行）；根包与应用服务的既有测试同步补齐清理。
- 不引入任何数据库 schema 变更；除导入返回结构的警告字段外不改变任何现有 API 契约。

### Testing Decisions

- 好的测试只断言外部可观察行为：服务方法的返回值与错误、事件流内容、落盘文件/目录的最终状态、构造出的启动命令本身；不断言内部调用次数或实现细节。
- **代理模块**：沿用现有 httptest 代理缝——配置代理时请求经过代理、空配置时环境变量代理生效、loopback 目标直连三条外部行为各一测。先例：现有代理契约测试。
- **MCP 认证层**：新纯函数缝直接断言各平台产出的命令与完整 URL；URLOpener 注入缝验证调用链。先例：现有 OAuth 测试对 URLOpener 的注入用法。
- **会话引擎**：fake SSE 模型 + 事件流钩子缝做回归——慢响应轮次进行中触发重新生成 / 删除，断言裁剪后事件流完整、无复活写入；配合 -race 全量回归。先例：现有确认 / 并行会话测试。
- **知识索引**：假 embeddings 服务器缝覆盖：目录删除后清空、单文件失败时保留其他文件、失败清单随错误返回。先例：现有语义检索测试。
- **文件工具与产物预览**：以大于上限的真实文件断言截断行为与上限内文件的完整读取；不测内存指标本身。
- **配置服务**：导入含悬空引用的分享文档断言清洗结果与警告；两个规范化同名技能导入断言冲突跳过。先例：现有技能导入测试。
- **记忆服务**：含 % / _ 的查询断言字面匹配。先例：现有记忆服务测试。
- **MCP 管理器**：以真实长驻子进程断言全量断开后进程退出、重复调用幂等。
- 全量验证继续走现有验证脚本；Windows 与 macOS 双平台各跑一轮作为验收证据。

### Out of Scope

- chatservice 与聊天页超大文件的拆分重构（另行立项）。
- A2A 服务端鉴权、绑定地址与对外暴露策略的变更。
- 知识索引加锁粒度与检索性能优化（仅修复"部分失败丢弃全部结果"的行为问题）。
- 会话元数据从配置文件向 SQLite 的迁移、配置文件写入频率优化。
- 前端确认框（window.confirm）替换为应用内 Dialog。
- 守护规则（密钥正则 / 注入检测）的覆盖面增强。

### Further Notes

- 缝的选择遵循「现有缝优先」：全部复用公开服务方法、事件流钩子、httptest 假模型 / 假 OAuth / 假代理、可注入 URLOpener；唯一新增缝是浏览器启动命令构造这一个纯函数，位于 MCP 认证层内部最高点。
- 问题来源为本会话对后端全部核心包与前端聊天主链路的通读审查；Windows 实测复现了 5 个测试失败与 OAuth 授权截断两个平台问题。
- 实施按 AGENTS 约定：每轮修复在迭代日志顶部追加记录，提交采用约定式前缀；建议拆分为平台正确性、会话一致性、资源安全、导入体验四个提交序列。
